# Game Automation Foundation（游戏自动化基础框架）

本目录用于沉淀可迁移到不同 Unreal Engine 游戏项目的自动化基础设施。现阶段内容来自 OBT 项目中的 `GameAutoPlugin` 与 UAuto 控制端，是一套**参考基线**，并非已经完全解除项目依赖的成品框架。

## 目录说明

| 目录 | 作用 | 当前通用性 |
| --- | --- | --- |
| `01_游戏侧插件_参考实现` | 在 UE 游戏进程内提供 TCP 服务、命令注册、UI 查询、输入注入、角色与场景接口 | 核心可复用，`GameAPI.cpp` 和 Build.cs 需要解耦 |
| `02_Python驱动SDK` | 从 Python 连接游戏，发送命令并封装 UI、角色、场景操作 | 大部分可复用，通信协议应升级 |
| `03_设备控制` | PC、Android、iOS 的安装、启动、停止、截图、录屏和设备状态操作 | 接口可复用，平台实现需清理环境依赖 |
| `04_数据采集` | 截图、性能、日志、场景和异常数据采集 | 架构可复用，上传地址和项目参数需配置化 |
| `05_执行与调度_参考实现` | 用例加载、前置步骤、重试、超时、设备调度和结果上报 | 仅作参考，当前内网服务耦合较重 |
| `06_角色自动化_参考示例` | 感知、选目标、移动、交互、战斗和异常恢复示例 | 属于项目业务示例，不应进入通用核心 |
| `docs` | 分层架构、迁移边界和从零实施路线 | 通用文档 |

## 推荐目标架构

```text
测试用例 / 业务流程
        ↓
Python Automation SDK
        ↓
版本化通信协议
        ↓
UE GameAutomationCore 插件
        ↓
ProjectAutomationAdapter
        ↓
项目角色、UI、任务、怪物与玩法系统
```

## 使用原则

1. 保留 `GameAutomationCore` 中的网络、协议、UI、输入和通用 World/Pawn 能力。
2. 把所有具体游戏类型、任务、怪物、机关和 GM 能力移入 `ProjectAutomationAdapter`。
3. 用例只能依赖 Python SDK 的稳定公开接口，不能直接依赖 TCP 文本格式。
4. 真实输入、导航移动和测试辅助操作必须分开标记，避免测试结论混淆。
5. Shipping 包默认关闭自动化端口；测试包通过编译开关、启动参数和访问控制显式启用。

详细拆分方式见 [跨项目迁移清单](docs/跨项目迁移清单.md) 和 [从零搭建路线](docs/从零搭建路线.md)。
