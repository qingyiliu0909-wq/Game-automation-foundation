# 从零搭建路线

## 第一阶段：通信最小闭环

- 创建 UE Runtime 插件和可控的启动开关。
- 在游戏主线程建立命令调度器。
- 实现长度前缀 JSON 协议、握手、心跳、请求 ID 和统一错误结构。
- 完成 Python 客户端的连接、超时、重试和能力查询。
- 使用 `ping`、`get_info` 连续调用进行稳定性测试。

## 第二阶段：UI 自动化

- 导出当前可见 UI 树。
- 支持按路径、名称、类型和文本定位控件。
- 支持文本读取、点击、输入、滚动和存在性判断。
- 为每个操作提供显式等待，并在失败时自动截图和导出 UI 树。

## 第三阶段：角色和场景

- 获取 Pawn 位置、朝向、速度和移动状态。
- 注入真实按键、摇杆轴、鼠标和触摸输入。
- 提供导航移动、到达判断、无路径、卡住和超时状态。
- 查询通用 Actor、Tag、Transform、Component、距离和可见性。
- 将传送、改速度等测试辅助能力与真实输入能力分组。

## 第四阶段：项目适配

- 实现玩家、敌人、任务目标、机关和交互物查询。
- 实现项目加载状态、战斗状态和结算状态识别。
- 用一条“感知 → 选目标 → 移动 → 交互 → 验证”流程验收闭环。

## 第五阶段：设备与工程化

- 实现 PC、Android、iOS 的设备发现、安装、启动、停止、截图和录像。
- 实现崩溃、卡死、断线和用例超时恢复。
- 采集日志、截图、录像、性能和测试步骤时间线。
- 接入本地或 CI 调度，多设备并行执行。

## 每阶段交付标准

每一阶段都需要同时交付：接口契约、最小示例、自动测试、错误码说明和迁移文档。不要等全部功能完成后再补协议和验证。
