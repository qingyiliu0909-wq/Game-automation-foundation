# 黑盒执行器接入说明

`05_执行与调度_参考实现/blackbox_runner` 是独立于游戏内插件的 UI 自动化参考实现，适用于登录、主界面、设置、商店、战斗入口等可由屏幕或 Android 原生控件确认的流程。

## 接入边界

| 放入项目配置的内容 | 保持在框架中的内容 |
| --- | --- |
| 游戏 exe、窗口标题、包名、设备序列号 | YAML 解析、重试、超时、报告格式 |
| UI 模板图、Android 控件标识、业务用例 | Windows / Android 驱动实现 |
| 日志、崩溃和录屏目录 | 截图归档与外部产物复制机制 |
| 项目专属弹窗处理与启动准备 | 通用步骤 DSL |

## 推荐落地方式

1. 在项目仓库创建 `automation/`，复制 `blackbox_runner/`、`examples/` 和空的 `assets/`。
2. 以 `examples/smoke-template.yaml` 为起点，新建具体用例；不要修改框架内核来写业务流程。
3. Windows 项目先为每个关键界面采集小而稳定的模板图；Android 项目优先使用稳定的 `resourceId`。
4. 通过命令行传入 exe / 标题 / 包名 / 设备和 `--artifact-source`，不把机器路径写进框架源码。
5. 在 CI 中保存 `results/` 目录并读取 `report.json` 或 `junit.xml`。

## 已知限制

- Windows 的模板识别会受分辨率、缩放、语言和 UI 动画影响；重要断言应设定清晰锚点并先固定测试环境。
- Android 的默认实现不支持图像识别，使用 `android_uia` 锚点更稳定；若游戏不暴露原生控件，需要接入图像识别或游戏内自动化插件。
- 角色、路径规划、GM、关卡状态等玩法语义属于项目适配层，不能归入黑盒执行器。
